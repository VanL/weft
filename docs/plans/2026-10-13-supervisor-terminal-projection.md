> TaskMonitor may reconcile a retained operational collation without terminal task-log proof from exact typed terminal evidence in that task's configured standard ctrl_out, using the same evidence selection and task-owned-before-supervisor precedence as the public task read model. Family disposition or a recorded cleanup pass does not end reconciliation: include disposed families while the collation is retained. Project the selected envelope's outcome and retain its source, including task-owned envelopes available only in ctrl_out. Compare each completed inspection with the persisted selected control observation through that same selector: removal of its source row does not let a later supervisor fallback demote a previously observed task-owned verdict. Task-log terminal proof still takes precedence. Preserve the envelope's reported time, exact queue/message identity, and the Monitor's first observation time separately; a missing reported time remains unknown. Missing runtime state or process alone supplies no terminal outcome. A later task-owned terminal verdict supersedes the supervisor projection regardless of their timestamp order. Ordinary nonterminal lifecycle updates must not demote an already observed control-terminal outcome. Evidence first published after the final verified empty ctrl_out inspection preceding physical family retirement is outside this retained-evidence guarantee. Control reconciliation does not recreate retired collations; ordinary task-log ingestion and retention remain unchanged. Do not extend retention indefinitely.

> This operational projection changes operational status and provenance in diagnostics only. It leaves terminal_seen, terminal_status, terminal_event, terminal_message_id and reserved_probe_needed unchanged, preserving the absence of task-owned terminal task-log evidence. It does not manufacture a lifecycle event, advance global-log bounds/high-water marks with a control-queue ID, consume a result, or grant additional inbox/reserved deletion authority under [OBS.13.7]. A changed selected terminal identity/outcome clears summary_emitted_at_ns in the same store transaction; replay of unchanged evidence does not. Task-log terminal evidence superseding a control projection performs the same invalidation. A corrected summary may be emitted for an already-disposed family without undoing or broadening its disposition. Structured lifetime reporting retains exact provenance and gives different selected evidence different stable report identities. Existing high-water, report handoff/verification, live-owner, launch-custody, and retention gates still apply before control evidence is removed or the family retires.

> Reconciliation uses the existing Monitor maintenance cadence, family batch bound, task-log scan row budget, and cleanup slice deadline. Candidate rotation and unfinished control scans remain bounded process-local state. Each scan inspects a fixed queue horizon in resumable pages and reduces candidates with the shared selector, keeping only its best envelope. Exhausting a page or time budget is incomplete inspection, not proof that task-owned evidence is absent. Only a fully inspected horizon may publish its selected control outcome. Probe failure preserves the collation/evidence and remains retryable without starving other families. Reconciliation runs independently of global task-log catchup; corrected summary emission retains its existing high-water gate. No additional watcher or polling service is introduced.

> For a retained family without terminal task-log proof, control-evidence deletion is limited to the fully inspected horizon whose selected evidence has completed the existing report handoff/verification. Later ordinary publications survive that deletion and remain eligible for reconciliation while the collation exists. Full control-cleanup completion and physical collation retirement use a final verified empty inspection of ctrl_out, not merely a prior cleanup-pass marker: a successful public queue-stat read must report total == 0, including pending and claimed rows. This inspection is the retained-evidence guarantee's boundary; queue inspection and collation retirement are separate operations. A publication after that inspection may outlive a retired collation without another collation correction report. Preserve that queue row during this retirement; subsequent ordinary dead-TID cleanup keeps its existing retention/reporting policy. Control reconciliation does not recreate retired collations; ordinary task-log ingestion is unchanged. A cleanup-pass marker may record ctrl_in-only progress while ctrl_out is retention-protected; it neither proves full control cleanup nor blocks the later reserved and dead-TID cleanup slices. A failed inspection defers retirement and remains retryable. Concurrent exact-ID operator restoration or moves behind an inspection cursor require paused Monitor cleanup and discarded continuations before resumption.

### Concrete boundary decisions

Reconciliation lifetime: use one retained candidate query, `terminal_seen=0`, scoped to the store's context and ordered by immutable TID with a rotating seek cursor. Do not filter on `disposition_at_ns` or `task_control_deleted_at_ns`: the latter can record a cleanup pass that removed only ctrl_in while ctrl_out was still retention-protected. Validate configured standard control queues before probing; custom queues stay outside this slice. In the projection transaction, re-read the current collation and select between its persisted control observation and the newly completed scan using the shared selector; task-log proof wins over both. Within a control precedence class the latest broker message ID still wins. Empty scans and lower-precedence supervisor evidence cannot erase a previously observed task-owned verdict. This retained observation remains derived status/provenance, never task-log cleanup authority. Ordinary cleanup still decides when retained evidence may end; before deleting that family's control evidence or physically retiring its collation, finish its bounded inspection and verify a report for the currently selected evidence. An incomplete scan or failed report handoff defers that family's cleanup/retirement, not the whole worker. Apply this fence to both existing family and dead-TID control cleanup paths when a retained collation exists. Keep all current active-owner and launch-custody checks; an earlier pass marker is not proof that retained completion evidence has been removed.

Deletion coverage: carry a completed scan's horizon through the same worker operation's report verification and cleanup; do not discard it before cleanup or carry an open iterator across operations. When current policy permits ctrl_out deletion, remove only covered rows with public `delete_from_queues((ctrl_out,), before_timestamp=horizon)` followed by `delete_message_ids(ctrl_out, (horizon,))`. Keep other queues on their existing policies. A task/Manager publication arriving after the scan receives a higher broker ID and survives this cutoff. If the final queue inspection sees it, defer full cleanup/retirement and reconcile it in a later bounded scan. Retirement's boundary is the final verified empty queue inspection outside the sidecar transaction; publication after that inspection may survive physical collation retirement without another projection/report. Do not recreate retired collations or delete those later queue rows as part of this retirement. Recheck the existing SQL eligibility gates in the deletion transaction, so intervening summary invalidation still blocks retirement. Failed inspection defers retirement. A restart or a separate cleanup invocation takes a fresh bounded scan; old scan progress cannot authorize deletion. This uses the existing broker's committed-ID ordering, not a new Weft transaction primitive. Deliberate exact-ID restore or move into ctrl_out can insert behind any cursor: operators must pause Monitor cleanup for that operation and discard scan continuations before resuming. Concurrent backdated operator mutation is outside this slice's guarantee; ordinary task publication and older-ID evidence already present in the inspected horizon remain covered.

Bounded reads: add a small windowed control reader in `weft/core/task_evidence.py`, sharing coercion, selection, and snapshot construction with the existing complete reader. Use public `peek_generator()` range/batch parameters and `latest_pending_timestamp()` to capture a finite horizon; close the iterator at every window boundary. Scan rows strictly before that horizon, then inspect the horizon row by exact ID through the public peek API, counting it in the same budget. Do not add one to the horizon and risk overflowing the message-ID ceiling. Count every inspected raw row, including malformed and mismatched rows. A worker invocation examines at most `batch_size` families and `task_log_scan_limit` raw control rows in total, stopping between broker calls at the existing `TASK_MONITOR_RUNTIME_CLEANUP_SLICE_SECONDS` deadline. Bound generator prefetch by the remaining row allowance; these are work bounds, not a promise to interrupt an individual blocked broker call. Do not call the complete reader once per maintenance candidate.

Keep at most `batch_size` unfinished scan values (TID, queue, horizon, last inspected ID, best envelope) in the current rotation. Round-robin their windows, filling freed slots from the same candidate query; a failed read releases its slot and advances candidate rotation so other families progress, with that family retried on a later wrap. A fixed finite horizon lets a busy queue finish despite newer writes. After its same-operation handoff/cleanup use, discard a completed continuation and start a fresh horizon from the beginning when that family is revisited, so older evidence restored between paused-cleanup cycles is not permanently skipped. Losing continuation state on restart causes bounded replay, not a different verdict. Do not add an unbounded per-TID cache, persistent cursor, polling cap, or scheduler framework.

Provenance and reports: use one small typed control-observation value and persist its bounded JSON representation in existing diagnostics. Retain `source`, `status`, `queue`, `message_id`, optional `reported_at_ns` from the envelope's `timestamp`, `first_observed_at_ns` from Monitor time, and bounded error. Existing snapshot `observed_at` is a broker message ID; do not relabel it as wall-clock observation time. Extend shared snapshot metadata to preserve the reported time without changing producer payloads. Unchanged selected queue/message/source/status retains its first-observed time and does not dirty summaries on every maintenance pass.

Use the existing summary path for corrections: in the high-water-gated summary phase also select retained, already-disposed rows whose summary marker was cleared by a changed selected verdict. Re-emit using the existing close reason and sink/handoff policy, mark the new summary only after successful verification, and leave disposition and deletion-policy fields intact. A stored historical control observation must be labeled superseded when task-log proof wins; reports must identify the selected evidence separately from that history. Extend `stable_report_id()` with the selected terminal queue/message/source/status (task-log identity when task-log proof wins), excluding scan progress and first-observed/emission time. Identical evidence on retry/restart keeps its ID; different evidence has a different ID even when raw global-log bounds are unchanged. Extend the actual task-summary external projection and lifetime-report external projection/deferred restoration for each new nested message-ID field using the existing exact message-ID format. Do not add a task-summary shape to the lifetime codec; no production deferred task-summary consumer exists. No new report kind, table, schema migration, or history list is needed.
